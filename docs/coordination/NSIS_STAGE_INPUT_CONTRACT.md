# Offline NSIS stage input contract design

`scripts/nsis_stage_input_contract.py` is separate from every production build/NSIS/workflow. `validate(stage, contract, external_inputs=())` reads only an absolute temporary fixture root. It executes no input, creates no output and returns immutable metadata with installerReady=false.

Required independent bindings: schemaVersion1, lowercase40hex sourceCommit, numeric Semver version; profile `{name: nsis-stage-synthetic-v1, version, sourceCommit, windowsTarget: x64}`; compile `{phase: unsigned-build, cwd: '.', entry: tools/makensis.exe}`; signing `{phase: deferred-human, enabled: false}`; output `{path: out/LTTH-Setup-<version>.exe, cwd: '.', overwrite: false}`. Input records have exactly path/role/sha256/cwdBinding/outputBinding. Every input is a canonical relative stage file. All actual files must equal declared paths with exact case; undeclared files, existing outputs, external_inputs, traversal/control/wildcard/reserved paths, links/junctions, hardlinks, hash drift and target case/ancestor collisions fail closed.

Role namespaces: compiler uses the fixed tools/makensis.exe path; nsis-script/sdk-include/sdk-resource/sdk-plugin live under build/ and have null outputBinding. Runtime payload targets app/ or node/; launcher targets launcher.exe; locales build-src/locales/; UI launcher.ico or build-src/assets/. Each noncompile payload target is explicit. Unknown fields/roles and role-target mismatches reject. Signing is only a deferred binding; neither certificate nor OTP is accepted.

Limitations: this is a read-only contract inspection, not a locked immutable byte snapshot. Concurrent filesystem replacement remains a later lock-layer integration gate. Input hashes and sourceCommit require separately trusted approval; roles do not inspect PE format or parse NSIS include/macro closure. No claim that a hostile NSIS script cannot name an external source: external_inputs only rejects references supplied by a future trusted closure analyzer. This contract must never be substituted for that analyzer or compiler sandbox. Full SDK closure, source provenance, timeout/job handling, output signatures and installed-data rollback remain separate requirements. It does not authorize a build/install/sign/release.

Checks: `C:\Python314\python.exe -B scripts/test_nsis_stage_input_contract.py -v` (14 synthetic tests). From app: `..\runtime\node\node.exe node_modules/jest/bin/jest.js --runInBand test/nsis-stage-input-contract.test.js` reruns those same tests. No compiler/signing calls, only mklink for owned temporary junction fixture cleanup.


Adversarial revision: Windows reserved-device matching uses Python ntpath.isreserved per component, including superscript COM/LPT digits, CONIN$/CONOUT$ and space-before-extension aliases. Version digits are strictly ASCII. The output namespace out/ must be absent before preparation, so declaring a preexisting output as an input cannot bypass overwrite=false. Duplicate entries/unsupported signer roles and input CWD/hash casing have explicit regressions. Benign Unicode filenames remain permitted; no Unicode normalization of contents or paths is performed, exact stage case is required.

Parser entry: load_contract(text_or_bytes) uses object_pairs_hook at every object depth and rejects duplicate decoded keys or NFC-equivalent keys. It preserves original keys/values and rejects nonfinite JSON constants, malformed/trailing JSON, UTF-8 decoding errors/BOM, non-object top level and inputs over 1 MiB. Pass its result to validate(). Direct dictionary callers still cannot recover duplicate evidence discarded by another loader. Returned metadata does not freeze live paths: replacing files with junctions or hardlinks after validate returns remains outside the no-lock contract. Future consumer must acquire locks and revalidate final handles before reading; the result must not be used as runtime sandbox authority.

The reviewed prototype requires Python 3.13+ for ntpath.isreserved (tested with 3.14); it is not integrated into workflows currently pinned to Python 3.11. Compatibility must be addressed before integration, not inferred from these tests.
