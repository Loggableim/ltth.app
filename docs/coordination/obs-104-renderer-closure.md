## Smallest bounded family: Advanced Timer

The existing Advanced Timer JSDOM fixture is the smallest useful isolated renderer family in this set: DOM/CSS only, no audio or GPU path, fixed `fixture-timer-{locale}` IDs, GET-only synthetic API responses, and a deterministic in-memory Socket.IO shim. Its pinned file manifest is [obs-104-advanced-timer-fixture.json](obs-104-advanced-timer-fixture.json): four local browser sources plus four plugin locale files, **291,020 bytes** total.

The manifest pins `app/plugins/advanced-timer/overlay/index.html` because that is the JSDOM entry. The canonical plugin-root route `/advanced-timer/overlay` separately serves `app/plugins/advanced-timer/overlay.html`; it is not covered by the JSDOM entry pin. A distinct saved [synthetic loopback browser receipt](evidence/advanced-timer-reconnect-20261007-final/browser-receipt.json) binds both entries, the current Timer/i18n files and capture host before and after a real Chromium Socket.IO reconnect. Its [before](evidence/advanced-timer-reconnect-20261007-final/before-disconnect.png) and [after](evidence/advanced-timer-reconnect-20261007-final/after-reconnect-paused.png) screenshots show running `01:30` green, then the offline-updated paused `01:15` orange. The host reported one reconnect state GET, zero ticks, and closed with no clients.

The Timer manifest itself validates directly against its eight current files. The aggregate nine-family fixture-contract suite currently has two failures because other family manifests still pin an older `app/public/js/i18n-client.js` byte count; those owner manifests and the shared validator were left unchanged. The shared validator remains frozen at SHA `4CA5B27C6A4CE2C73B74813A2B027A83ECC6407898394D5EBC10B91E10F1EE2F`.

Its consumer contract is limited to:

- Asset requests: `/socket.io/socket.io.js` (the CPU fixture provides an in-memory shim; the pinned browser bundle is not executed by JSDOM), `/js/i18n-client.js`, and `/plugins/advanced-timer/overlay/overlay.js?v=3`.
- Synthetic GETs: locale translation reads and `/api/advanced-timer/timers/{fixtureId}` plus the optional `/rotator` and `/threshold-effects` reads. The fixture returns memory-only responses with rotator/threshold disabled; it does not seed a timer or run the plugin backend/database.
- Renderer consumes ten timer socket events; the bounded scenario delivers only `advanced-timer:tick` with a matching synthetic ID and a mismatching-ID negative. Page-hide cleanup disconnects the shim. No actual loopback listener, WebSocket handshake, Socket.IO browser client, plugin route, OBS or VM is started.

The pinned manifest validator checks exact source allowlists, root containment, every path component for symlink/reparse points, regular-file status, byte count and SHA-256, locale completeness, and no profile/credential/runtime-state paths. Synthetic negative tests exercise traversal, forbidden user-state paths, changed size/hash, simulated reparse metadata, unknown manifest fields and attempts to broaden the runner contract. The optional `/api/i18n/locales` consumer exists in the shared i18n client but the current fixture scenario does not call it; fixture requests are asserted against observed route logs.

The linked [Timer fixture evidence bundle](obs-104-renderer-fixture-evidence.md) binds the current **26/26** combined Timer/Goals Jest result to the current eight-file manifest, test and helper hashes. Its JSDOM transport remains synthetic; the separate Chromium receipt establishes only the local fixture-host reconnect, not the product server or OBS.

## Second selected safe family: STT Ticker

STT Ticker has a three-file static renderer closure plus four plugin locales, seven files / 275,488 bytes. It is the smallest low-risk follow-up family by static byte size among the 3-file candidates: its CSS and renderer JavaScript are inline in `ticker.html`, with only the shared i18n client and Socket.IO browser bundle as separate scripts. The CPU fixture intercepts both assets and substitutes an in-memory socket shim. It supplies only synthetic transcript/interim/clear events and translation GETs; STT capture, provider services, audio and the STT plugin backend remain excluded. The same file count appears for Game Engine and Music Bot, but their matrix scopes are blocked and include broader game/API state or dynamic artwork/audio concerns.

The [STT Ticker fixture manifest](obs-104-stt-ticker-fixture.json) pins this seven-file set and the exact route/event allowlists. Its external-reference count is zero. The closure inventory records one line-specific dynamic risk: shared i18n client `app/public/js/i18n-client.js:79` fetches `${translationBase}/${locale}`; the fixture narrows that to `/api/i18n/translations/{de|en|es|fr}`. The same i18n client contains a fixed `/api/i18n/locales` consumer at line 286, but this fixture does not call or allow it; the new STT negative-route test explicitly calls it and observes the interceptor's `unknown-route` 404. The renderer reads parent-theme/localStorage state; JSDOM has no external parent frame and any localStorage is ephemeral. That ambient state is not payload data and must not be bridged to a host profile. The renderer also registers `connect`, `disconnect`, and three `stt-ticker:*` socket consumers; tests drive only synthetic transcript/interim/clear events and never connect a real transport.

The current source-backed STT fixture is [obs-stt-renderer-fixtures.test.js](../../app/test/obs-stt-renderer-fixtures.test.js) with [its isolated helper](../../app/test/helpers/obs-stt-renderer-fixture.js). ## Third selected safe family: Goals

By full pinned closure size (static renderer sources plus the four locale files), Goals is the next small safe family after excluding the already accepted Advanced Timer/STT fixtures, Talking Heads (out of scope and dynamic sprite assets), Minecraft Connect (unsupported public entry), and GPU-dependent WebGPU Weather Control. Goals is 275,523 bytes across eight files: `overlay/index.html`, its `overlay.js`, shared i18n client, Socket.IO browser client source, and `de/en/es/fr` locales. It is SVG/DOM, with no GPU, audio, external URL or unresolved local file reference. The [Goals fixture manifest](obs-104-goals-fixture.json) pins this exact closure.

Its one line-specific unresolved dynamic risk is the shared translation template `${translationBase}/${locale}` at `app/public/js/i18n-client.js:79`; the fixture contract fixes reads to the four locale paths. The same client contains a fixed `/api/i18n/locales` consumer at line 286, but this is not an allowed Goals fixture route or requested by the Goals renderer scenario; a separate STT negative-route test explicitly attempts and rejects it. The renderer's query `id` and socket payload IDs are dynamic product inputs; tests constrain them to `fixture-goal-{locale}` and reject mismatching IDs. Event producers and the plugin database are not started. The event consumers are `connect`, `disconnect`, `goals:animation-end` (outbound), `goals:config-changed`, `goals:deleted`, `goals:error`, `goals:reach-complete`, `goals:reached`, `goals:reset`, `goals:subscribe` (outbound), `goals:subscribed`, and `goals:value-changed`.

The targeted existing source suite filtered to Goals passed **7/7** with 15 unrelated Timer tests skipped; it covers all four locales, initial subscription, matching/mismatching IDs, update, not-found/service error recovery, queued response/animation cleanup, BFCache restoration and the existing unsubscribe handler contract. This is synthetic in-process evidence, not a real Socket.IO or OBS result.

## Talking Heads and TTS — read-only missing dependencies

- Talking Heads renderer static sources include its HTML, overlay CSS/JS, shared i18n client and the browser Socket.IO bundle, with four locale records. Product behavior still needs `app/plugins/talking-heads/main.js`, its `engines/asset-sprite-library.js` and `engines/animation-controller.js`, the `/api/talkingheads/config` producer, Socket.IO server producers/payload schemas, and locally pinned avatar sprite URLs/assets. The renderer receives sprite URLs in runtime events; the static crawl cannot close that dynamic asset set. These producer/asset dependencies are not added to a payload here.
- TTS is not a renderer entry in the 104-case matrix. A TTS integration would need `app/plugins/tts/main.js`, `event-tts-handler.js`, shared utility modules and a deliberately selected engine (for example TikTok, Google, Speechify, ElevenLabs, OpenAI, FishSpeech or SiliconFlow) with its package/provider/network requirements. Provider credentials and user configuration are excluded. This task made no TTS or Talking Heads changes.
